# Задание opencode: исправить многостраничную сборку Vite

Работай из корня проекта mte. Выполни изменения, а не только предложи план. Это задание разрешает редактирование перечисленных ниже файлов для исправления сборки. Не меняй чужие изменения и не делай commit/push.

## Контекст и проблема

Прочитай `.opencode/tester.md` и `.opencode/stage-1/README.md`.
Приложение — Tauri 2 + React + Vite. Окна создаются Rust-кодом по адресам:

- html/home.html
- html/backtest.html
- html/api-keys.html
- html/chart.html
- html/positions.html

Исходные HTML уже находятся в `client-tauri/html/`. Сейчас `npm run build` проходит tsc, но Vite пытается собрать корневой index.html со ссылкой на отсутствующий /src/main.tsx.

## Область изменений

Разрешены только `client-tauri/vite.config.ts`, `client-tauri/index.html` и существующие `client-tauri/html/*.html`, если исправления в HTML действительно нужны. Rust-файлы, tauri.conf.json и package.json можно читать для понимания путей, но не менять.

Не изменяй React-компоненты, Python, стратегии, зависимости и lock-файлы. Не добавляй заглушку src/main.tsx ради прохождения сборки. Не отключай TypeScript/ESLint и не подавляй ошибки. Не выполняй массовое форматирование.

## Что сделать

1. Проверь реальные entrypoints HTML и соответствие путям WebviewUrl::App в Rust.
2. Настрой Vite как многостраничную сборку всех пяти существующих страниц. Пути в dist должны соответствовать адресам Rust без его изменения.
3. Определи осмысленное поведение корневого index.html: он может вести на существующую главную страницу или использовать её entrypoint. Ссылки на отсутствующие файлы не должно остаться. Не создавай вторую реализацию главного экрана.
4. В конфигурации ESLint сейчас стоит fix:true. Убери автоматическую запись исправлений при dev/build, сохранив диагностику: проверка сборки не должна массово менять исходники.
5. Сохрани dev-порт 1420, strictPort и существующую поддержку Tauri/HMR.

Используй установленную версию Vite и локальные зависимости. Если всплывает блокер за пределами разрешённых файлов, зафиксируй точную ошибку и остановись с отчётом; не расширяй задачу самостоятельно.

## Проверки

Из `client-tauri`: `npm run build`.
Проверь, что dist/html содержит все пять страниц и ссылки на JS/CSS ведут к существующим файлам внутри dist. Не ограничивайся кодом возврата сборки. Проверь отсутствие ссылок на /src/main.tsx и исходные TSX в выходных HTML.
Сравни изменения до и после проверки: сборка не должна переписывать React-компоненты или lock-файл. Не откатывай чужие изменения, если они уже были в рабочем дереве.
Не запускай GUI и не устанавливай зависимости для этой задачи. Новые тестовые фреймворки не нужны.

Укажи изменённые файлы и причину, результат npm run build, список выходных HTML, результат проверки ресурсов и ограничения проверки. Не заявляй, что desktop-приложение проверено, если проверена только web-сборка.
