# Этап 1: воспроизводимый запуск и подключение

Цель: Python и Tauri запускаются по инструкции; все окна попадают в сборку; окно тестера показывает реальное состояние соединения, получает списки данных/стратегий и понятно сообщает об ошибках.

На этом этапе не исправляем исполнение сделок, статистику, pause/resume, восстановление прогона и загрузчик биржевых данных. Не переносим стратегии. Работающий запуск не означает готовность всего тестера.

## Порядок и исполнители

1. Opencode выполняет `01-build.md`: многостраничная сборка Vite без изменений Rust/Python и компонентов React.
2. Codex проверяет diff и сборку. Одновременно с задачей 1 может работать над подключением в Rust/React: файлы не пересекаются. Работать в одном checkout допустимо только в указанных границах; не делать общий commit чужих изменений.
3. Codex проверяет приложение целиком, в том числе отсутствие Python, его поздний запуск, обрыв и восстановление соединения. Выявленные ошибки старта исправляются в рамках этапа.
4. Opencode выполняет `02-runbook.md` после готовности сборки и подключения: документация отражает фактические команды и поведение.
5. Codex проводит итоговую приёмку и отмечает фактически проверенные сценарии. Только после этого переходим к управлению сессией.

## Задача Codex: соединение

- Источник истины — Rust bridge. Состояния connecting / connected / disconnected; отдельная последняя ошибка подключения. Не смешивать состояние транспорта со статусом теста.
- Sender доступен только при установленном соединении; сбрасывается при разрыве. Команда при отсутствии подключения сразу возвращает понятную ошибку, а не остаётся в очереди на будущее.
- Автоматическое переподключение с задержкой без цикла, нагружающего CPU. Ошибки записи также закрывают текущую попытку подключения.
- Tauri-команда чтения актуального состояния плюс событие изменения состояния. Инициализация подписки/чтения должна исключать применение устаревшего состояния; поздно открытое окно тоже показывает правильное подключение.
- После подключения/переподключения окно запрашивает актуальные списки стратегий и файлов. Не полагаться на начальные события, отправленные до открытия окна.
- UI показывает подключение, отсутствие сервера и восстановление; ошибки invoke видны пользователю, не только в console. Start недоступен без соединения и загруженной доступной стратегии. Не отправлять Stop как побочный эффект ошибки отправки Start.
- Успешный invoke означает отправку команды, а не запуск движка. Не показывать «тест запущен» до ready. Подтверждения команд и таймауты загрузки данных подробно прорабатываются на этапе 2.

Область: `client-tauri/src-tauri/src/commands/backtest_commands.rs`, регистрация команд в `src-tauri/src/main.rs`, `src/apps/backtest/` (типы, hook, экран и кнопка запуска). Python меняется только при доказанном блокере запуска; не переписывать SessionManager в рамках этого этапа.

## Приёмка

- [ ] `npm run build` успешен; в dist/html есть home, backtest, api-keys, chart, positions и их ресурсы.
- [ ] `cargo check --offline` успешен.
- [ ] `npm run tauri dev` открывает главное окно и Backtest без пустой страницы.
- [ ] При выключенном Python отображается понятное состояние; Start недоступен, нет бесконечного начального Loader.
- [ ] Поздний запуск Python приводит к подключению и появлению списков без перезапуска Tauri.
- [ ] Открытие Backtest после уже установленного соединения корректно загружает списки.
- [ ] Остановка/повторный запуск Python отражается в UI и обновляет списки; команды, отправленные без соединения, не исполняются позже.
- [ ] Закрытие/открытие окна без активного теста сохраняет корректное состояние подключения. Восстановление активного теста относится к этапу 2.
- [ ] Контрольный запуск существующего CSV достигает ready и выдаёт свечи; финансовая корректность пока не критерий этого этапа.
- [ ] Инструкция содержит рабочие каталоги, порты, установку зависимостей и ограничения; проверенные сценарии отделены от непроверенных.

Готовность native release-пакета с подписью, установщиком и встроенным Python не входит в этап. Здесь проверяем web production-сборку и запуск desktop в dev.
